# 세이버 노트 — 진행 기록

데모 HTML(`docs/saber-note-demo.html`)을 React + TypeScript 앱으로 옮기는 작업의 현재 상태입니다. 새 대화는 이 문서와 `docs/개인 PRD (최종).md`를 먼저 읽고 시작합니다.

- **마지막 갱신**: 2026-11-07 (완료)
- **현재 상태**: `main`은 시연판 **완료** (2026-11-07). 0~6단계, 7-1단계, 시연 준비를 마쳤고 7-2(Supabase 연결)는 하지 않기로 했다(아래 결정). 실행 방법과 시연 진행은 `README.md`
- **브랜치** `feature/theme-and-expression`: 응원 팀 배경과 커뮤니티 표현 범위 조정 **0~7단계 완료** (2026-11-07). `main`에 합칠지와 GitHub에 올릴지는 사용자 결정 대기. 9절 참고
- **검증**: `npm run check`(타입 검사 · lint · 테스트 171개) 통과, `npm run build` 통과
- **브라우저 확인**: 2026-11-07 사용자가 `npm run dev`로 전체 화면을 확인했고 문제없었다 (커뮤니티 사진·영상 미리보기·재생, 새로고침 후 유지, 다른 탭 반영, 다크 모드, 휴대폰 폭 포함). 시연 준비 뒤에도 홈런 궤적 예시 사진, 신고 시연(3번째 신고로 가려짐), 시연 데이터 초기화를 사용자가 확인했다. 작업 환경에서는 브라우저를 띄울 수 없어 자동 검사는 jsdom 테스트로만 한다.

## 결정: 7-2(Supabase 연결)는 하지 않는다 (2026-11-07)

- **결정**: 커뮤니티를 서버(Supabase)에 연결하는 7-2단계를 진행하지 않는다. 커뮤니티는 브라우저 저장(IndexedDB)으로 남는다.
- **이유**: 이 앱은 공식 배포용이 아니라 **기능 구성을 보여 주는 시연용**이다. 시연에는 한 브라우저 안에서 글쓰기·작성 제한·신고·선수 카드 연동이 동작하는 것으로 충분하고, 서버·로그인·저장 비용·운영 정책(PRD 미확인 항목)을 갖출 필요가 없다.
- **남겨 둔 것**: 저장소 인터페이스(`data/source.ts`의 `CommunityRepository`, `storage: 'shared'` 포함)와 서버에서도 쓸 수 있게 만든 작성 제한·글 규칙(`domain/community/`)은 그대로 둔다. 나중에 서버를 붙이게 되면 7절의 7-2 계획을 출발점으로 쓴다.
- **대신 한 일 (시연 준비)**: 처음 열어도 커뮤니티가 비어 보이지 않게 "데모 게시글" 예시 글을 넣고, 커뮤니티 화면에 "시연용이라 글이 이 브라우저에만 저장돼요" 안내를 넣었다 (4절 23·24번).

## 1. 실행

```bash
npm install
npm run dev        # 개발 서버
npm run check      # 타입 검사 + lint + 테스트
npm run build
npm run golden     # 데모 HTML에서 골든 데이터 다시 추출 (fixtures/demo-golden.json)
```

도구: Vite 8, React 19, TypeScript 6, React Router 8, Vitest 5(+ jsdom, Testing Library), oxlint.

## 2. 구조와 규칙

```
src/
├─ data/     ① 불러오기 — 리그를 아는 유일한 층 (demo/, mlb/, community/, 나중에 kbo/)
├─ domain/   ② 계산·규칙 — 리그를 모르는 순수 함수 (metrics/, games/, community/, 카탈로그, 백분위, 비교 …)
└─ ui/       ③ 화면 — 기능별 폴더 player · compare · games · community, 공통은 shared
```

- **층 경계** (`.oxlintrc.json`, `no-restricted-imports`로 강제)
  - data → domain·ui·react import 금지
  - domain → `data/types`만 import 가능 (domain 테스트 파일은 데이터 출처 import 허용)
  - ui → 리그 어댑터(`data/demo`·`mlb`·`kbo`·`community`) 직접 import 금지, `data/registry`를 거친다
- **값 없음 규칙**: 해당 없거나 모르는 값은 언제나 `null`. 원시 데이터 타입에 선택 필드(`?`)를 두지 않는다. domain의 리그 평균·백분위·비교는 `null`·`undefined`·`NaN`을 모두 값 없음으로 보고 분자·분모에서 뺀다 (`domain/missing.ts`).
- **데이터 출처 계약** (`data/source.ts`, `data/types.ts`)
  - `load()` → 원시 기록 + 리그 상수 + `meta`(시즌 표기, 계산 기준 문구, 반영일, 출처, 안내 문구, `available`)
  - `meta.available`: 기록 필드 하나하나의 있음/없음. 없다고 한 필드는 모든 선수에게 null이어야 한다 (`unavailableButPresent`로 검사). domain의 `metricAvailable`이 지표 → 원시 필드를 연결하고, 화면은 없는 지표 줄을 숨기고 보여 줄 것이 없는 탭을 닫는다.
  - `loadBattedBalls(id)`, 선택 함수 `loadWeek(weekId, ids)`(없으면 세이버 픽 챌린지를 닫는다)
  - 단위는 km/h · m/s · 0~1 비율로 바꿔서 넘긴다.
- **커뮤니티 저장소 계약** (`data/source.ts`의 `CommunityRepository`): 글 목록·구독·쓰기(파일 포함)·좋아요·신고·삭제·파일 주소. `storage`는 browser(이 브라우저에만)·memory(새로고침하면 사라짐)·shared(서버). ui는 `data/registry`의 `openCommunityRepository`로 연다. 작성 제한 검사·가림·자동 태그는 저장소에 넘기기 전에 domain(`domain/community/`)이 한다.
- **골든 테스트**: 데모 HTML을 jsdom에서 실행해 뽑은 값(`fixtures/demo-golden.json`)과 새 계산을 대조한다. 데모와 일부러 달라진 곳은 `demoQuirks`에 기록하고 테스트에서 예외로 처리한다.
- **CSS**: 색상·글꼴은 `ui/shared/tokens.css`에만 둔다. 나머지는 `base.css`·`metric.css`(공통)와 기능별 CSS.

## 4. 데모와 일부러 달라진 결정

데이터·계산
1. **지명타자 수비 항목**은 17개 모두 명시적으로 null (데모는 일부만 null, 나머지는 아예 없음). 테스트: `data/demo/demo.test.ts`
2. **DRS·OAA의 -0**을 0으로 정규화 (데모의 `Math.round`가 -0을 냄)
3. **리그 평균·백분위에서 값 없음 제외**: 데모의 리그 평균 수비율 NaN, 지명타자가 분모에 섞여 낮게 나오던 수비율 백분위를 고침. 골든 테스트에서 `fpct` 백분위만 예외. 테스트: `domain/percentile.test.ts`
4. **`regular`(주전) 플래그 제거**: 리그 상수 `qualifiedPA`(300타석)로 판단. 투수는 규정 이닝 기준이 아직 없어 데모처럼 전원을 비교 대상으로 둔다.
5. **0 표시 규칙**: 반올림한 결과가 0이면 부호 없이 표시("-0.0"·"+0.0" → "0.0"). 데모의 15건은 `demoQuirks.signedZeroFmt`. 테스트: `domain/compare.test.ts`, `domain/league.test.ts`
6. **지표별 있음/없음**: 출처에 없는 지표 줄은 숨기고(예: MLB의 DRS), 비교 화면에서도 뺀다. 탭은 안에 있는 지표가 하나라도 있으면 연다.

화면
7. **주소 기반 화면**: `/player/:id`, `/compare?a=&b=`, `/games/:game`. 상단 메뉴는 버튼 대신 링크(CSS `nav button` → `nav a`)
8. **CSS 추가 규칙 3개**: 닫힌 탭 흐리게, 키보드로 고른 자동완성 항목 강조, 메뉴 링크. 규칙 안에 직접 쓰던 색(#fff, 그림자, 오버레이, 백분위 막대 색)을 토큰으로 옮김. 백분위 막대 색은 `color-mix`로 같은 선형 보간
9. **자동완성 키보드 조작**(↑↓ Enter Esc), 검색 결과 없음 안내의 "위의 많이 찾은 선수" → "아래의"
10. **수비·트래킹 탭 아래 "데이터 출처 · 반영일"** (PRD 화면 5). 수비 탭 설명 문구는 실제로 보이는 지표만 나열

미니게임
11. **블라인드 퀴즈**: 한국 날짜 시드로 하루 1문제 모두 같은 문제(PRD), 푼 뒤 연습 문제. 보기 섞기는 고른 섞기(Fisher–Yates)로 바꿈
12. **세이버 픽 챌린지**: 주차(ISO, 한국 시간, 월요일 시작) 시드로 같은 문제. 주간 기록은 출처의 `loadWeek`로 받고, demo는 주차·선수별 시드로 시뮬레이션(데모는 매번 `Math.random`). 순위표는 "가상 참가자, 데모"로 표시. 채점 기준 문구는 `meta.basisLabel`
13. **이 타구, 안타일까?**: 수비수는 **그 팀에서 그 포지션 수비 이닝이 가장 많은 선수**(300타석 기준 아님, 동률은 목록에서 먼저 나온 선수, 없으면 수비 보정 없음). 출처에 없는 기록(스프린트 스피드, OAA, DRS, 능력치)은 보정·표시에 쓰지 않는다. 출처가 타구 데이터를 줄 때만 연다.
14. **지표 업다운**: 출처에 있는 지표만 문제로 낸다.
15. **게임 화면은 연 시각으로 날짜·주차를 고정**한다 (렌더링 중 자정을 넘겨도 문제가 바뀌지 않게).

커뮤니티 (7-1)
16. **저장소**: 데모의 claude.ai 공유 저장소 대신 브라우저 저장(IndexedDB, 사진·영상 파일 포함). 쓸 수 없으면 메모리 저장으로 바꾸고 "새로고침하면 사라져요"라고 알린다. 같은 브라우저의 다른 탭에도 바로 반영(BroadcastChannel). 예시 게시글은 7-1에서는 넣지 않았다가 시연 준비에서 넣었다(23번).
17. **거친 표현 가리기 버그 수정**: 데모는 띄어 쓴 표현("존 나")을 찾고도 가리지 못했다. 찾은 표현이 원문에서 차지한 구간 전체(사이의 공백·숫자 포함)를 ●로 가린다 ("존 나" → "●●●"). 테스트: `domain/community/community.test.ts`, `src/community.test.tsx`
18. **오탐 줄이기**: "시발점"·"시발역"·"시발택시"는 허용 낱말로 두어 차단하지 않는다 (데모는 차단).
19. **전화번호 검사**: 공백·하이픈·점을 모두 지운 뒤 010·011·016~019로 시작하는 10~11자리를 찾는다 (데모는 구분자를 하나씩만 허용).
20. **도배 제한**: 저장소에 남은 "내 마지막 글" 시각 기준이라 새로고침해도 유지된다 (데모는 메모리 값).
21. **삭제는 자기 글만**: 데모의 "편집 권한자는 모두 삭제"는 운영자 기능이라 넣지 않았다(7-2를 하지 않기로 해서 운영자 기능도 없다). 작성자 이름은 "나"/"팬", 예시 글은 "데모 게시글"(로그인이 없어 프로필은 없다).
22. **걸러 보기를 주소에 남김**: `/community?player=…&media=1`, 선수 카드의 "이 선수 글쓰기"는 `&write=…`로 태그를 미리 단 글쓰기 칸을 연다.

시연 준비
23. **"데모 게시글" 예시 글 6개**: 리그 기록(홈런·도루·탈삼진 1위 등)으로 글을 만들어 태그·숫자가 리그 화면과 맞는다. 하나에는 사진(홈런 궤적 그림, SVG)이 붙는다. 작성자 자리에 "데모 게시글"로 표시되고 아무도 지울 수 없다. 저장소에 함께 저장되어 좋아요·신고가 남고, 열 때마다 작성 시각을 "25분 전"·"3시간 전"…처럼 지금 기준으로 다시 맞춘다(시연 날짜가 언제든 오래된 글로 보이지 않고 "이번 주 많이 이야기된 선수"에도 잡히게). 코드: `data/community/seed.ts`, 작성자 id `DEMO_AUTHOR_ID`(`data/types.ts`). 테스트: `data/community/seed.test.ts`, `src/demo-community.test.tsx`
24. **시연 안내**: 커뮤니티 글쓰기 칸 제목 아래에 "시연용이라 글이 이 브라우저에만 저장돼요. 새로고침해도 남지만 다른 사람에게는 보이지 않아요."를 늘 보여 준다(IndexedDB를 못 쓰면 "새로고침하면 글이 사라져요"를 덧붙임). 게시 결과·오류 안내는 그 아래 줄에 따로 나온다.
25. **신고 시연용 예시 글**: 6개 중 하나(`demo-post-6`, "[신고 시연용] …")는 가상의 다른 시청자 2명(`DEMO_REPORTERS`)이 이미 신고한 채로 시작한다. 시연자가 신고를 누르면 3번이 되어 가려지고 "그래도 보기"로 펼칠 수 있다. 신고는 저장되어 새로고침해도 가려진 채로 남는다(다시 보여 주려면 26번 초기화).

## 7. 7단계 계획

데모의 공유 저장소(`window.claude` db·assets·user)는 claude.ai 전용이라 쓸 수 없다. 그래서 둘로 나눈다.

### 7-1. 저장소 인터페이스 + 브라우저 저장 버전 (완료)

> 아래는 착수 전에 세운 계획이다. 실제로 한 일과 달라진 점은 4절 16~22번과 커밋 메시지를 본다.
> 만든 파일: `domain/community/{moderation,posts}.ts`, `data/community/{browser,memory,shared}.ts`, `data/registry.ts`의 `openCommunityRepository`, `ui/community/*`, `ui/shared/SearchBox.tsx`(선수 검색 상자를 공통으로 옮김), `ui/shared/useNow.ts`. 테스트: `domain/community/community.test.ts`, `data/community/community.test.ts`, `src/community.test.tsx`

**목표**: 데모 커뮤니티의 화면과 기능을 브라우저 저장만으로 완성한다. 새로고침해도 글과 사진·영상이 남는다.

배치
- `domain/community/` — 리그·저장소와 무관한 규칙. **서버(7-2)에서도 그대로 쓸 수 있게** 브라우저 API(DOM, `window`, IndexedDB)와 외부 패키지에 의존하지 않는 순수 TypeScript로 둔다.
  - `moderation.ts`: 작성 제한 규칙(심한 욕설·혐오·비하·위협·전화번호는 차단하고 걸린 표현과 이유를 알려 줌, 거친 표현은 ●●로 가림, 띄어쓰기·숫자·기호를 끼운 우회 표현 걸러내기). 표현 목록은 데모 `MOD`에서 옮긴다.
  - `posts.ts`: 게시 검사(본문 또는 파일 필수, 파일 최대 4개·20MB·PNG/JPG/WEBP/GIF/MP4/WEBM), 30초 도배 제한, 본문 속 선수 이름 자동 태그, 신고 3번 누적 시 가리기, 선수별 관련 글 수·최근 24시간 글 수, 이번 주 많이 이야기된 선수
- `data/community/` — 저장소
  - `repository.ts`: `CommunityRepository` 인터페이스 — 글 목록 구독/불러오기, 글 쓰기(미디어 포함), 좋아요 토글, 신고, 삭제, 미디어 주소 얻기, 현재 사용자
  - `browser.ts`: 브라우저 구현. 글과 사진·영상 파일(Blob)을 **IndexedDB**에 저장. 미디어는 Blob URL로 보여 주고 다 쓰면 해제. 사용자는 기기별 로컬 사용자 하나
- `ui/community/` — 커뮤니티 화면(글쓰기·미리보기·선수 태그·작성 제한 안내·필터·피드·좋아요·신고·삭제·가린 글 펼치기·이번 주 많이 이야기된 선수·작성 규칙), 선수 카드 아래 "커뮤니티 이야기"(관련 글 N개, 최근 24시간 M개, 최근 글 2개, 관련 글 모두 보기, 이 선수 글쓰기)
- 저장소는 ui에서 컨텍스트로 주입(리그 데이터 출처와 같은 방식). 테스트에서는 메모리 구현을 넣는다.

데모에서 고칠 것
- **거친 표현 가리기 버그**: 데모는 띄어쓰기를 지운 문장으로 거친 표현을 찾고(`normTxt`), 가릴 때는 원문에서 그대로 찾아 바꾼다(`maskMild`). 그래서 "존 나"처럼 띄어 쓰면 "가려진다"고 안내만 하고 가리지 않은 채 게시된다. 원문 위치에 맞춰 가리도록 고치고 테스트한다.
- 선수 ID는 `리그:번호` 문자열(데모는 숫자)
- 데모의 시드 게시글("데모 게시글")을 둘지는 7-1에서 정한다.

테스트
- 작성 제한 규칙(차단·가림·우회 표현·전화번호·오탐 예시), 게시 검사, 도배 제한, 자동 태그, 신고 가리기, 집계
- 브라우저 저장소: IndexedDB 저장·새로고침 후 복원(테스트용 IndexedDB 구현 패키지 사용 검토), 삭제 시 미디어도 삭제
- 화면: 글쓰기 → 피드 표시, 차단 안내, 신고 3번 → 가림 → 펼치기, 선수 카드 연동

- **거친 표현 가리기** 설정 값(`maskProfanity`, 기본 켜짐)은 2단계에서 저장소에 미리 넣었고, 켜고 끄는 버튼은 실제로 가리는 기능과 함께 6단계에서 화면에 붙인다.
결정과 구현 메모 (5~6단계: 커뮤니티 표현 범위)
- **판정 순서**: ① 누구를 향하든 차단(패드립·협박·혐오·비하·성적 모욕·개인정보) → ② 다른 사용자를 향한 욕 → ③ 선수·심판·감독·코치 → ④ 대상 없는 사람 비하 → ⑤ 나머지 일반 욕은 허용. 차단이 하나라도 있으면 애매함보다 우선한다.
- **「병신」**은 원래 단어와 띄어쓰기·숫자 우회 표현 모두 혐오·비하(장애)로 차단. **「ㅂㅅ」**은 일반 욕(상황·플레이에 쓰면 허용, 사람을 향하면 인신공격).
- **다른 사용자**: 2인칭(너·넌·니가·너네 …)·글쓴이 지칭이 욕과 **바로 붙어 있으면(사이 2글자 이하)** 차단, 같은 문장 안에서 떨어져 있으면 애매함. 처음 기준표의 "10글자 이내 차단"을 사용자가 지정한 문장 "니 말이 맞다 X발 오늘 대박 → 애매함"에 맞춰 좁혔다. 2인칭은 띄어쓰기로 나뉜 낱말 하나일 때만 세서 "너무", "아니", "언니"는 지칭이 아니다.
- **선수·심판·감독·코치**(선수는 성을 포함한 전체 이름, 심판·주심·감독·코치 등 직함): 사람 자체 비하(외모·존재·이·저·그+호칭)는 **플레이 낱말보다 항상 우선**해서 차단(사용자 요청). 외모 낱말 중 "얼굴·생김·외모" 같은 중립 낱말은 욕과 함께일 때만 비하로 본다. 플레이·직무 낱말이 있는 일반 욕은 허용, 없으면 애매함.
- **애매함**: 게시 전에 이유와 함께 「고쳐 쓰기」/「그래도 올리기」. 그래도 올리면 `caution: true`(「주의」 표시), 걸린 표현은 읽는 사람 설정과 상관없이 늘 가린다.
- **저장 방식 변경**: 예전에는 쓸 때 ●로 바꿔 저장했지만, 이제 원문을 저장하고 화면에 보일 때 가린다(`useShownText`). 예전에 ●로 저장된 글(`masked: true`)은 그대로 보이고, `caution`이 없는 예전 글은 읽을 때 `false`로 채운다(`normalizePost`).
- **오탐 줄이기**: "시발점·시발역·시발택시·새끼손가락"은 허용 낱말. 붙여 쓴 "이년"은 "이년차"와 겹쳐서 보지 않는다. "죽인다·죽여주네"(칭찬 표현)는 협박 목록에 넣지 않았다. 문장은 물음표·느낌표·줄바꿈, 마침표 뒤 공백으로만 나눠 "씨.발" 같은 우회 표현이 쪼개지지 않게 했다.
- **개인정보**에 주민등록번호 형태를 추가했다.
- **예시 글 7개**: "오늘 수비 진짜 ●같네… 9회에만 실책 두 개라니"(허용되는 수준의 욕, `demo-post-7`)를 추가했다. 4절 23번의 "6개"는 `main` 기준이다.
